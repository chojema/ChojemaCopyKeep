# Privacy and Local Storage

[한국어](PRIVACY.ko.md) | [README](../README.en.md)

## Collection and Retention

The app stores text and images copied while it is running in a local database. Source app names, window titles, and keystrokes are not logged. Clipboard content from before launch is not imported automatically.

History and settings are stored in `%LOCALAPPDATA%\ChojemaCopyKeep\history.db`, or the separate folder selected for development. The app does not encrypt its database. Access to stored files is managed through Windows accounts and folder permissions.

In macOS 0.2.0 and the Windows source build, user-created snippets are stored in the same database. They are kept separately from clipboard history, so clearing history and applying the history limit do not delete them. Delete snippets individually from the snippet list. Snippets are not encrypted by the app.

## Transmission

The app has no clipboard upload feature, account login, cloud synchronization, usage collection, or automatic update downloads or installation. The GitHub repository and releases contain source and distribution files only.

Selecting `Check for updates` in Windows or macOS 0.3.0 or later makes an HTTPS request to GitHub for the latest stable release location. GitHub and configured network proxies may receive normal connection information such as your IP address and app name. Clipboard content, snippets, and settings are not included. There are no startup or periodic checks. Confirming the update prompt opens the official release page in your default browser.

## Pausing Collection and Deleting History

Collection can be paused from the notification area menu. Individual items can be deleted, and clearing all history requires confirmation. Clearing history removes the app's stored records; the current system clipboard and content pasted into other apps remain unchanged. Secure erasure of storage media is not guaranteed.

The app skips items marked for exclusion by their source apps. It does not automatically classify passwords or personal information by content. Collection can be paused before copying sensitive content.

## Development and Publication

Exclude stored content, personal settings, credentials, logs, internal work records, private email addresses, and personal paths from the repository and distributed files. Use synthetic examples in public issues and screenshots.
## macOS storage and permissions

macOS history and settings are stored in `~/Library/Application Support/ChojemaCopyKeep/history.db`. The app creates the directory for access by the current account only and the database for reading and writing by that account only. It does not encrypt the database. SQLite may create journal files in the same directory on either operating system.

The macOS app skips ConcealedType, TransientType, AutoGeneratedType, 1Password markers, and file URLs. Clipboard changes are checked every 0.5 seconds, so rapid consecutive copies can miss intermediate items. Accessibility permission is used to locate the insertion point and send the paste shortcut to the original app. When entries have abbreviations, text replacement monitors input events and temporarily holds at most 65 ASCII characters in memory. Monitored input is never saved to disk, logged or transmitted. Clicks, navigation, app changes and pausing clear the input buffer. Password fields and secure input are excluded; replacement requires verification of the exact abbreviation and insertion point. Clipboard collection also works without Accessibility permission.

## Text replacement

Version 0.4.0 stores abbreviations and replacement content alongside existing snippets in the local database. Existing entries are retained with empty abbreviations and require an abbreviation for automatic replacement. Windows also keeps monitored input in memory only, without logging or transmission. Replacement content is copied to the system clipboard and may be collected by other clipboard managers. Pausing stops both clipboard collection and text replacement.
